# From immutable interpretation storage to live decisions

The original risk was a late baseline turning an unsupported historical package quantity into a number. Storage alone could preserve an unresolved check while the live calculator or duplicate matcher still ignored it. This checkpoint connects the existing interpreter to analysis writes, current-context comparison and numeric duplicate candidates.

The shared SQL selector supplies bounded trusted metadata. Analysis captures encountered past source keys, reloads their server-derived state, verifies source bytes and hashes the final snapshot. An unresolved check remains incomplete until a separate source-backed decision is approved. A deterministic capture race retains one shared check, and transaction failures leave no partial analysis or capture.

Freshness compares stable observation/check/review identities, excluding mere clock passage. Legacy package analyses with insufficient context become explicitly unknown; a later resolution invalidates current advice while keeping the saved receipt exact. Numeric duplicate matching resolves each source independently and never treats two unavailable quantities as equal.

Independent review identified an unbounded metadata callback under an explicit helper option, and representation overhead missing from the final byte cap. Both were repaired and regression-tested. Exact-code Linux CI passed 513 tests / two skips, plus Ruff and Marimo. The full Windows run passed **514 tests / one real-OCR skip / five warnings / 862.56 seconds**.
