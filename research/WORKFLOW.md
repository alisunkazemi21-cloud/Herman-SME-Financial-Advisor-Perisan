# Evidence-preserving workflow

Each stage follows this sequence:

1. Review repository evidence and relevant literature.
2. Discuss scientific choices and unresolved risks.
3. Record the decision and alternatives before implementation.
4. Implement traceable inputs and validation checks.
5. Run short checkpoints before long production work.
6. Analyze stationarity and uncertainty before interpretation.
7. Synchronize the run README, research chapter, technical report and media narrative. Maintain consistency with the app's manifest; interface development is currently deferred.

Before processing real documents, run the tests and, where OCR is used, the three labeled reference cases with accounting review. Engine confidence alone never authorizes posting. Each run links artifacts through a common run ID and input hash. Label synthetic data explicitly.

## Language policy — user instruction, 2026-10-06

Use English for repository prose, research, decisions, comments, checkpoint notes and generated Markdown reports. Keep Persian app text, RTL presentation, source documents, fixtures and business data unchanged. Report templates must follow this split so later checkpoints do not reintroduce Persian documentation prose.

For the translation checkpoint, previously committed narrative Markdown may be translated as explicitly requested. Preserve source data, input snapshots, manifests, evidence bytes, IDs, hashes and recorded numerical results. Git retains the original-language narrative history. Existing filenames and links may remain for compatibility.
